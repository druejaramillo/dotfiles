# Frame a feature

Framing decides **what problem matters now**, not how to implement a solution.
A Frame Go authorizes time to shape; it is not a bet to build. Keep the frame
separate from the later Shape Up pitch.

## Process

1. Read the candidate, available customer evidence, product context, existing
   behavior, and prior decisions. When candidates compete, compare what
   happens *without* each one rather than ranking imagined solutions. Read a
   supplied issue or file; ask only for facts or decisions you cannot find.
2. Identify the specific people and situation. Ask: **What are they doing
   instead today? What's bad about that?** Trace a concrete case through the
   present workflow where possible. Separate demonstrated pain from
   assumptions and requested solutions from the underlying problem.
3. Narrow the problem to a recognizable outcome and baseline: what changes
   for those people if it is solved? State why it matters now and what happens
   if nothing is done. Narrow grab-bags such as “improve the dashboard” until
   the focal problem is clear.
4. Propose an **appetite**: how much controlled team time this problem is worth.
   It constrains the solution; it is not an estimate for a design already
   chosen. Check whether this is sizeable, schedulable feature work. Route
   urgent small fixes, routine maintenance, and externally blocked work
   through the project's ordinary process instead.
5. Present the frame with evidence, assumptions, alternatives set aside, and
   the smallest remaining human decision. Recommend **Frame Go**, **more
   evidence**, or **not now**. The user decides whether to spend time shaping.
   Do not design a full solution or declare approval on their behalf.

## Output

- **Candidate and affected people:** who, when, and what currently happens
- **Baseline and cost:** present workaround and consequence; evidence versus
  inference
- **Desired outcome and why now:** what should change, not a feature list
- **Proposed appetite:** time and controlled contributors; why it is worth it
- **Recommendation and decision needed:** Frame Go / more evidence / not now;
  uncertainties worth investigating during shaping

Present the frame in conversation by default. Save it only if the user asks or
an established project workflow requires a file. If the frame changes during
shaping, explicitly revise the problem rather than preserving an outdated
premise.
