# Claim-to-evidence audit

Audit a paper against code, a report against data, or another precise claim
against its underlying artifact.

1. Identify the claim-maker, wording, date/version, authoritative artifact and
   comparison dimensions.
2. Inspect exact paths, settings, processing, tables or passages. Compare
   defaults, exclusions, data, metrics/units, test conditions and version
   differences. Read scholarly/PDF references when applicable.
3. Classify each finding as matches, mismatch, unverifiable or interpretation.
   Missing public code is not itself a contradiction.
4. Explain consequences, severity and the smallest useful follow-up. A
   read-only audit does not execute repository code to fill a gap; an execution
   check follows the replicate playbook and its authorization.

Use the requested location or `outputs/<slug>-audit.md` for a substantive
audit. Include claimed versus observed evidence, URL/path with locator,
classification, consequence and reproduction/verification limits. Honor an
explicit chat-only or no-write request instead of forcing a report file.
