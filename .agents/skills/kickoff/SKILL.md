# Kick off an approved pitch

Use the pitch/file supplied with the request or the approved pitch in the
conversation. Read the full pitch and linked concept specs. If the pitch or
build decision is missing, ask for it. Kickoff is not permission to place a bet.

Read `~/.agents/skills/shape/references/shaping-tools.md` for the DUMP and
AFFINITIZE exercise. When the pitch names concepts or synchronizations, also
read `~/.agents/references/concept-integrity.md`.

1. Walk through problem, appetite, solution, rabbit holes and no-gos.
2. Surface questions for shapers/builders instead of guessing decisions.
3. Help builders dump imagined tasks, then cluster them into a few initially
   unnamed groups. Name tentative integrated scopes only after clustering.
4. Identify uphill scopes and an early risky end-to-end slice that could
   demonstrate actual behavior.

The scope map is provisional. Builders own implementation and may redraw
scopes/tasks as they learn. Do not preassign tasks, publish tickets or begin
coding just because kickoff was requested. Present the map and remaining
questions in conversation unless the user wants an artifact.
